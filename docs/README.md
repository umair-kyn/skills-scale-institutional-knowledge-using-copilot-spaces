# OctoAcme Project Management Docs

Welcome to the OctoAcme project management documentation suite. These guides define the standard practices, roles, and artifacts used to plan, deliver, and improve cross-functional work across the organization.

## Overview of the OctoAcme project management process

OctoAcme uses a lightweight, iterative project lifecycle designed to keep teams aligned from idea to delivery and continuous improvement. The process emphasizes:

- Customer-first decision making
- Clear ownership and accountability
- Iterative delivery of small, testable increments
- Data-informed tracking and measurable outcomes
- Open communication, risk management, and learning

The project lifecycle follows five connected phases:

1. Initiation — validate the business need, define stakeholders, and create a high-level project brief.
2. Planning — break work into a backlog, estimate effort, define dependencies, and align the release plan.
3. Execution — manage day-to-day delivery, track progress, and resolve blockers and risks.
4. Release & Deployment — validate readiness, ship changes, and monitor success after deployment.
5. Close & Continuous Improvement — capture lessons learned and turn them into action items for the next cycle.

## Core principles

- Customer-first: prioritize customer value and usability
- Iterative delivery: ship small, testable increments
- Clear ownership: each initiative has defined leaders and responsibilities
- Data-informed decisions: use metrics and evidence to guide changes
- Psychological safety: encourage feedback, learning, and candid discussion

## When to use these docs

- During kickoff and early project alignment, start with the Overview and Initiation guide.
- During scope definition and planning, use the Planning guide and backlog templates.
- During execution, rely on the Execution & Tracking and Risk & Communication docs.
- Before and during deployment, use the Release & Deployment guide.
- After a milestone or incident, use the Retrospective guide to capture learning and action items.

These documents are intended to provide a shared operating model for OctoAcme teams and a simple path to guidance at every stage of a project.
